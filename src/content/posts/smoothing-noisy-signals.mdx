A sensor does not hand you the truth. It hands you a measurement: the thing you care about, mixed with uncertainty. Before reaching for a complicated estimator, it helps to understand what a very small filter can do.

> This is an example technical note with simulated data, not a report of a hardware experiment.

## Start with a running estimate

Suppose $x_t$ is the latest observation and $y_{t-1}$ is our previous estimate. We can update that estimate by moving a fraction of the way toward the new observation:

$$
y_t = \alpha x_t + (1-\alpha)y_{t-1}, \qquad 0 < \alpha \leq 1.
$$

The parameter $\alpha$ is the weight on new information. At $\alpha=1$, the estimate follows every observation. As $\alpha$ gets smaller, history matters more. This is an **exponential moving average**, a first-order infinite impulse response filter.

The useful question is not “How smooth can I make this?” It is “How much delay can my application tolerate?” An attractive curve can still be the wrong signal for a control loop.

## Implement the update

The recurrence needs one stored estimate. Initialize it from the first measurement instead of zero to avoid an artificial startup transient.

```cpp
class ExponentialFilter {
    double alpha;
    double estimate = 0.0;
    bool initialized = false;

public:
    // Precondition: 0 < smoothing && smoothing <= 1.
    explicit ExponentialFilter(double smoothing) : alpha(smoothing) {}

    double update(double measurement) {
        if (!initialized) {
            estimate = measurement;
            initialized = true;
        } else {
            estimate += alpha * (measurement - estimate);
        }
        return estimate;
    }
};
```

In production, validate the smoothing factor and decide how to handle missing or non-finite measurements. A `NaN` can otherwise poison every future estimate.

## Relate smoothing to time

For a sample interval $\Delta t$ and a desired time constant $\tau$, a useful coefficient is

$$
\alpha = 1 - e^{-\Delta t/\tau}.
$$

This corresponds to the exact sampled decay of a first-order system with input held constant over each interval. After one time constant, a step response covers approximately 63% of the distance to its final value. If the sample interval varies, recomputing $\alpha$ keeps the interpretation tied to elapsed time.

## Know the limits

Smoothing does not remove sensor bias, recover clipped measurements, or distinguish a real abrupt change from an outlier. It also introduces phase lag. For a controller, evaluate the complete loop before deciding that a quieter measurement is an improvement.

The small filter is valuable because its assumptions are visible: recent measurements are informative, change is gradual enough, and a little delay is acceptable.

### A useful next experiment

Replace the sine wave with a step. Measure the settling time at several values of $\alpha$. Then repeat with a changing sample interval. The gap between “samples” and “seconds” becomes much easier to see.
